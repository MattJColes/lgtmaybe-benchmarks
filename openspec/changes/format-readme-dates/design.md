## Context

Raw results store second-precision UTC timestamps and the report renderer currently writes those values directly into both complete and incomplete Markdown rows. The same rendered output feeds `RESULTS.md` and the generated README section.

## Goals / Non-Goals

**Goals:**

- Show `YYYY-MM-DD` in generated report date cells.
- Keep full raw timestamps and timestamp-based sorting unchanged.
- Use one small formatting function for complete and incomplete rows.

**Non-Goals:**

- Changing raw result timestamps, filenames, time zones, or ordering.
- Giving README and RESULTS different date formats.

## Decisions

Extract the calendar-date prefix from the validated ISO timestamp when rendering a row. This preserves the original string for sorting and avoids converting an already-normalized UTC value through locale-sensitive datetime APIs.

Apply the same formatter to complete and incomplete tables because both are generated by the same reporting interface and use the same date column contract.

## Risks / Trade-offs

- Multiple runs on one day display the same date, reducing visible precision. Their newest-first order still uses full raw timestamps, and exact times remain in raw JSON.
